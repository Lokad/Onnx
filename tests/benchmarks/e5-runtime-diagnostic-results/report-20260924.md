# Focused e5 runtime diagnostic

Four fresh processes run selected, candidate, candidate, selected with
unchanged M66 product binaries, normal .NET 10.0.8 settings and CPU 2.
Every original warmed-consumer statement remains; four observation hooks
add event markers and CPU/allocation/collection counters outside its timer.
CPU 0 collects and exports runtime events. Instrumentation changes runtime
history: these clocks do not qualify a release or replace the failed score.

Late runtime compilation overlaps the measured window in both products. The
last observed Lokad method loads occur at calls 606, 598, 601 and 652
respectively. In selected D, `Gather` reaches optimized Tier 1 at call 627,
`RunCoreInner` at 642, `ResolveInputs` at 643 and `BuildStaticAliasRoots` at
652. All 15,182 compilation start/load pairs reconcile, as do all suspension
pairs; no boundary event is unmatched.

Selected D's 600–659 block averages 24.340 ms and overlaps 712.029 ms of
compilation intervals versus 3.777 ms of GC suspension. Its later blocks
average 16.959 and 16.733 ms. This establishes that 600 warmups do not reliably
exclude runtime compilation in this program. It does not establish how much
of the original uninstrumented 6.769% result came from that mechanism.
