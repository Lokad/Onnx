## Resources and known numerical limits

AMD is EPYC 9V74, four vCPUs, 16 GiB without swap, runtime 10.0.8, with inference
confined to CPU 2 before CLR startup. Local execution uses runtime 10.0.12 and
AVX2. Both builds use SDK 10.0.204. AMD jobs run sequentially with normal runtime
settings, whole-process-group sampling and resource guards. No collection is
forced, and every job terminates before the next starts.

| Finite replay | Nine mechanisms disabled, peak GB | Defaults enabled, peak GB |
|---|---:|---:|
| AMD shared models | 1.54 | 1.92 |
| AMD Whisper public requests | 7.99 | 7.42 |
| AMD eight repeated Whisper requests | 11.07 | 9.80 |
| AMD dialogue API | 3.77 | 3.85 |
| AMD dialogue detailed capture | 3.75 | 2.82 |
| Local Parakeet | 5.87 | 6.92 |

GB means one billion bytes. These are observed process peaks, not an indefinite
memory bound or a claim that every model uses less memory. Local Parakeet and
AMD shared-model peaks increase in these runs. Whisper's repeated defaults
remain below the 13 GiB guard. Released-array and packed-weight budgets cover
their own caches, not all model weights, live outputs or runtime allocations.

The existing audio numerical gates remain open. Parakeet retains the same
three repeated English step-26 duration-logit discrepancies, maximum
`2.321004867553711e-4`. Dialogue retains 19 failed local filterbank values and
24 on AMD, with maxima approximately `1.636e-4` and `1.564e-4`; all other stages
pass. The earlier silence failures and Whisper encoder/logit failures are not
cleared by these application replays. Complete Parakeet AMD qualification,
broader accuracy and long-recording requirements remain separate work; see the
[support matrix](../../docs/model-support.md).
