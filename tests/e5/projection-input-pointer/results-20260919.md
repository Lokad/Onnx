# Packed-input pointer proof and AMD comparison — 2026-09-19

The pointer variant passes the planned machine-code and correctness proof but is rejected for product integration. Including scratch and copying, its 30-row bank is **2.11% slower** and its 128-row bank **2.83% slower** than the first original control. Both original controls satisfy their prospective stability limits. Every worker regresses both primary banks against each original control. No production code, default or tolerance changes.

## The verified instruction change

The [preceding experiment](../projection-input-pack/results-20260919.md) used twelve `input[j * 12 + row]` reads. This separate variant uses `input[row]` and advances the pointer by twelve floats after each reduction step. The activation copy, scratch lifecycle, row partition, packed B format, accumulating destinations, FMA order and all tails remain unchanged. The old indexing route is retained as a fourth mode alongside the two identical original controls and new pointer route.

A separate AMD proof worker completed before timing preparation. Its actual FullOpts loop uses one input base register (`r8`), literal byte offsets 0, 4, …, 44 and a 48-byte pointer advance. All three kernels execute 24 FMAs and twelve broadcasts per reduction step, with no vector stack accesses or hot-loop calls.

This satisfies the predeclared instruction gate. Five corrupted versions of the actual captured operands/advance are refused independently; the unit tests also reject dynamic indexes, bad offsets, changed registers, excessive instruction counts, spills and calls. The proof is closed before timing, and timing uses its exact binaries without rebuilding. The smaller instruction count is a code-generation result, not a performance conclusion.

## Complete-cost performance screen

Every candidate call includes scratch rental, the complete activation copy, destination clearing, computation, unchanged row tails and scratch return. Constant B weights alone are prepared outside steady-state timing. Four fresh processes use fixed orders 1/2/3/4, CPU 2 inherited before runtime startup, AMD EPYC 9V74 and .NET 10.0.8. Normal runtime/GC settings apply. JIT-output flags are used only by the earlier proof worker.

Each 72-matrix bank contains 84,934,656 packed weight bytes, with two complete bank warmups and seven measured samples per mode. Ratios below use each worker's median, then the geometric mean across four workers. Below one favors the pointer variant. Inputs are synthetic and independent; this is not complete e5 execution or an ORT comparison.

Eight and 512 rows required aggregate ratios at most 1.01. Original duplicates had to stay within [0.98, 1.02] in aggregate and [0.95, 1.05] in each worker. Controls pass; primary gains and the 512-row regression requirement fail. No sample or failed criterion was dropped, no threshold changed, and no unchanged rerun followed.

The pointer/indexing comparison is mixed at 128 rows. Removing the extra sign extensions does not establish that they dominated elapsed cost. The complete packing strategy remains slower than the original; this experiment does not separately quantify copy and pool costs. The earlier indexing rejection remains unchanged.
