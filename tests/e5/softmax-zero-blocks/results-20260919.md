# Masked softmax zero-block experiment — 2026-09-19

The padded-128 masked-softmax call takes about 39% less time when whole vector
blocks already guaranteed to become zero bypass the exponential polynomial.
All exactness checks pass. **The complete prospective screen fails:** one
eight-token worker exceeds the fixed 5% regression limit. The experiment does
not add a product switch, change a default, or establish a full-model gain.

## Mechanism and controls

The existing nonpositive exponential returns zero below `-88.722839f`, but
evaluates its polynomial with benign substituted inputs first. The candidate
adds an all-lanes check on the actual exponential arguments and returns the
same zero vector immediately. A NaN lane fails the check. Cutoff, coefficients,
maximum, reduction order, normalization and scalar tails are unchanged.

Four modes run in every worker: the actual frozen core method; a source-extracted
copy specialized to the existing nonpositive-on/wide-off defaults; the vector
skip; and an adaptive wrapper that chooses the copy when the mask contains no
entry below the cutoff. A negative mask only selects the candidate path: each
vector still checks its actual score-plus-mask-minus-row-maximum arguments.

The source extraction and its metadata reproduce byte for byte. The actual core
control prevents a difference introduced by extraction from silently becoming
the claimed improvement.

The frozen criteria require at least 15% padded-128 improvement in every worker
against the copy and in aggregate against the actual core; copied/actual
padded-128 control agreement within 3%; and unmasked regressions at most 2%
in aggregate and 5% in every worker. Every criterion passes except the last
eight-token worker bound: order 0 is 9.1474% slower. Padded-512 is a reported
stress case, without an acceptance criterion. These rules are a mechanism
screen, not calibrated confidence intervals or full-model acceptance.

## Timing limitation

The failed order-0 eight-token adaptive batch at sample index 3 records
430,052 ns wall time, 257,111 ns foreground-thread CPU and 432,863 ns process
CPU for 128 calls. The order-2 copied control has a similar sample: 411,964 ns
wall, 250,251 ns thread CPU and 414,635 ns process CPU. Other threads may have
consumed time, but these counters do not identify them or prove a JIT cause.
They bracket slightly different intervals and cannot give an exact decomposition.

No measured batch, including the disassembly process, records a GC. Maximum
foreign CPU fraction is 0.118221% of machine capacity, measured steal is zero,
and peak sampled worker RSS is 148,455,424 bytes. Low foreign load does not
remove the observed wall/thread discrepancy. No sample is discarded, replaced
by CPU time, or reclassified to make the prospective screen pass.

The mechanism remains promising for padding. Any follow-up must separately
qualify the resolution of these sub-millisecond batch measurements with
duplicate controls and a prospective protocol; it cannot rerun unchanged until
a favorable visit appears. Product integration also needs complete-model
semantics, resources and performance evidence. The existing e5 scoreboard is
unchanged.

## Correctness and generated code

Each of the nine AMD processes independently passes 2,503,712 exponential-lane
checks, 918 complete-tensor cases and four short-mask refusals. The same local
checks pass before staging. Coverage includes random negative bit patterns,
active arguments, cutoff neighborhoods, NaNs, infinities, signed zeros,
mixed vectors, widths 1–513, odd/even rows, SIMD/scalar paths, arbitrary masks,
input preservation and output guards. Copies, skip and adaptive results match
the actual frozen core bits. An additional independent double calculation has
maximum absolute error 2.477703762160388e-7, below its fixed 1e-6 bound.

The actual AMD Tier1 listing confirms three inlined skip sites. `IG19` uses
`vcmpltps` / `vptest` / `jb IG157`; `IG157` zeroes the vector and jumps to the
store/sum block `IG20`. `IG66` and `IG87` use `vcmpltps` / `kortestb` with
branches to `IG141` and `IG142`, which zero the result and jump to `IG67` and
`IG88`. Each taken branch bypasses the polynomial instructions. The separate
code capture also retains Tier0 and on-stack-replacement versions; the
instruction observation does not prove which version ran in every untraced
timing interval.

Seven audit tests pass, including sixteen malformed-data refusals and three
negative timing-screen cases. The initial auditor failed while hashing its own
`__file__` string as a Path; this occurred before writing the output. The
corrected helper accepts either form. That failure is retained, with no change
to data or criteria.
