This is a read-only, post-hoc description of all 160 original processes, 89,088 measured calls and 225,149 conditioning calls. All 1,820 files bound by the original closed receipt were rehashed. No sample, gate or previous verdict changes; no inference was run.

Spreads compare the largest and smallest of three identical managed processes within one visit. These are descriptive observations from four visits, not confidence bounds. Every process also has all 48 block means, four quarter means, full-sample mean/median/minimum/maximum, conditioning-tail mean, allocation range and GC counts in the retained analysis. Request-boundary observations are retained too.

The largest 30-token Memory contrast is visit 2: A/B/C average 17.608335 / 16.863369 / 16.612931 ms, with medians 17.573093 / 16.847638 / 16.601627 ms. All three record 39 generation-zero and two generation-one collections, with no generation-two collection; mean allocation is approximately 840,708 bytes per call. A remains between 17.5418 and 17.7019 ms across its four measured quarters. Thus the discrepancy is not explained by those collection counts, nor confined to a few exceptional measured calls. Neither engine allocation counters nor medians establish a clock, collector or code-generation cause.

Another worker, visit 0 / 512 tokens / Memory / A, moves from 354.6592 to 340.3710 ms between its first and last quarters. Temporal separation and persistent process differences both remain possible contributors. Simply deleting tails or adding a longer warmup is not justified by this evidence.

The next prospective experiment uses separate runtime/collector processes with short interleaved batches, suspending inactive processes, balancing local role order and retaining solo-versus-resident comparisons. It preserves all cases, policies and control thresholds. This changes execution scheduling; it does not retrospectively qualify the failed independent experiment. Physical-cache and memory effects must still be measured and disclosed.
