# Original Parakeet decoder recurrent constants

Read-only protobuf inspection confirms two LSTM nodes, each with hidden size
640 and separate constant W/R tensors shaped `[1,2560,640]`. All four tensors
are float32, embedded in the model, absent from graph inputs/outputs and consumed
only by their corresponding LSTM weight slot. No runtime was loaded or executed.

| LSTM node | W initializer | R initializer | Combined bytes |
|---|---|---|---:|
| `/decoder/dec_rnn/lstm/LSTM` | `onnx::LSTM_205` | `onnx::LSTM_206` | 13,107,200 |
| `/decoder/dec_rnn/lstm/LSTM_1` | `onnx::LSTM_225` | `onnx::LSTM_226` | 13,107,200 |

A same-sized float panel for each original tensor would total 26,214,400 bytes
(25 MiB). Added to the qualified decoder's existing 25,246,720 packed bytes,
the hypothetical total is 51,461,120 bytes, below its unchanged 67,108,864-byte
cap. This is a capacity calculation, not an observed new cache. Actual layout
size, refreshed accounting, source ownership, context propagation and route use
still require qualification before any speed claim.

Model: `models/parakeet-tdt-0.6b-v3/decoder_joint-model.onnx`, 72,520,893 bytes,
SHA256 `e978ddf6688527182c10fde2eb4b83068421648985ef23f7a86be732be8706c1`.
[Complete node metadata, weight digests and calculation](decoder-lstm-model-20260924.json)
are generated by `inspect_decoder_lstm_model.py` from that existing local model.
The [implementation review](decoder-lstm-source-review-20260924.md) explains
why the original branch's prepared route cannot be imported without adaptation.

No model was copied, no product was changed and no performance was measured.
