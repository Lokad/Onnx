# Padding fallback after ordinary runtime optimization

The unchanged M47 binary no longer reproduces the large fallback differences
in this one diagnostic pair after the prospectively fixed warmup. Cropping is
0.5353% slower, outer padding 1.5616% faster and reflection 0.9822% slower. This
supports compilation history as a material contributor to the old result.
It is not product qualification: both original screens remain rejected, and
the release comparison stays **53.107381 seconds versus ORT 39.207695**.

The [retained-evidence review](../pad-fallback-review-results/report-20260926.md)
selected this diagnostic before execution. Selected Core 521bae17 and rejected
Core 060950a1 are unchanged, with no compiler annotation or runtime override.
Only the consumer adds complete rehearsals before its original twelve-case
600/180 suffix. The same ten-second-after-first-census stopping rule produces
two selected rehearsals (44.915718 seconds) and six candidate rehearsals
(13.144247 seconds). The candidate's final rehearsal ends 10.930777 seconds
after its first. No duration or gate was adjusted after seeing timings.

The primary eight-case sum uses 94.9038% less time. There is only one instrumented
process per binary, so these ratios do not establish repeated-process performance
or a complete Parakeet improvement. They do not replace any failed screen gate.

The candidate's retained prefix shows the change within the same process. For
cropping, its six consecutive rehearsals' last-180 means are 0.189277, 0.177683,
0.179126, 0.190623, 0.148267 and 0.146615 milliseconds. These remain warmup
observations; none is selected as a score. Outer padding and reflection likewise
converge toward the selected timings. The previously observed extra 88 allocated
bytes also disappears: suffix median counters agree exactly at 56,176, 60,928
and 60,392 bytes respectively. Counters include instrumentation; this observation
does not locate an allocation or prove a particular compiler transformation.

The sole intervention was the prefix workload. It affects compilation, caches
and runtime history together. The trace and within-process change strengthen the
compilation explanation, but cannot assign every historical outlier to JIT or GC.
The prior M49 annotation still has a different dynamic-PGO policy and remains
rejected. No further annotation, neighboring kernel or duration sweep follows.

All eight jobs and owners are terminal with code zero. Independent prefix and
original suffix reconciliation cover **93,600 calls, 187,200 markers and 1,560
consecutive 60-call blocks**; both traces have zero lost events. The existing
oracle, immutable-input and independently owned-output checks pass. All 353
resource observations pass, with peak owned RSS 372,998,144 bytes. Five prefix
tests check valid retained calls and reject missing markers, wrong round counters,
insufficient elapsed warmup and overlapping prefix/suffix intervals.

The next implementation candidate is the already reviewed block-copy dispatcher
applied to the current root, preserving the generic fallback and all compiler
settings. Its motivation remains the exact Parakeet/ORT algorithm discrepancy:
48 nonnegative last-axis pads, contiguous copying versus per-element coordinate
mapping. Before integration it needs current-root compiled compatibility,
correctness and repeated-process screening using the prospectively fixed warmup;
then complete application and shared-model qualification. This diagnostic alone
admits no product or benchmark change.
