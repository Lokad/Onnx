# Corrected partial-sum dispatch passes Parakeet and shared-model qualification

The isolated Core `f2c292cb` preserves every original raw MathOps kernel and
retains the complete Parakeet native pass. **All 784 arrays / 3,090,494 values**
pass the unchanged `1e-4` bound, and all twenty public corpus requests pass.
Every native array is byte-identical to the preceding arithmetic candidate.

The full repository suites now pass: **3,101 backend tests, 93 skips, and 342
tensor tests**. This resolves the two failures in the preceding implementation:
the raw packed-kernel bitwise contract is preserved, and the additional DinoV3
hash pair was independently qualified against every native output value before
being added to the isolated test copy. Both previous hash pairs remain accepted.
Main product source and tests remain unchanged; the candidate is not promoted.

## Dispatch and geometry

The same helper adds independently accumulated 256-term FMA partial sums to
existing C. Admission remains positive rows, reduction at least 1,024, and
complete 32-column panels. No threshold was narrowed to evade failing tests.
Selection moves to the dynamic and prepared tensor dispatchers, after existing
AVX-512 candidates. Packing admission, budgets, wide-kernel precedence, dynamic
odd-row fixup and scalar paths stay unchanged.

The instruction comparison permits only `RunFloatMatMulKernel`,
`RunPreparedPackedRows` and one added internal helper. **3,084 other Core
methods, including every original raw kernel, and all 691 Data methods** match
frozen production instructions.

All 416 raw-kernel comparisons retain original bits. All 416 helper/prepared
geometry cases pass independent partial-sum or original fallback references:
64 admitted cases and 352 fallbacks. Checks cover nonzero destination values,
input and packed-weight ownership, output canaries, partial reduction blocks,
odd final rows and column tails. Forty-eight dynamic-dispatch cases match the
previous arithmetic candidate, including unpacked and remainder paths. Four
captured projections reproduce the selected arithmetic, and four
hardware-disabled refusal/public fallback cases pass.

## Resources, retained failures and scope

All 477 build/model, 78 shared-model, 357 suite and 687 pyannote resource
observations pass.
Native Parakeet peaks at 6,487,732,224 bytes RSS under 8 GiB, and its public corpus
at 9,121,869,824 under 12 GiB. The shared replay peaks at 2,383,998,976 under
8 GiB. Full backend tests peak at 3,169,521,664 under 8 GiB. All jobs bind CPU2
before runtime startup and retain available-memory, disk, output and time guards.
Pyannote peaks at 3,260,289,024 bytes under 8 GiB. All local experiment workers
and supervisors are terminal.

The first shared-replay preparation incorrectly required Data.dll in the original
Core-only consumer runtime. It failed before launching any inference. The
failure and copied files are retained; a separate successor preserves the
original Core-only dependencies. The suite launcher also initially had a
missing Python `Path` import, corrected before any suite artifact or child was
created. Neither failed preparation is counted as a successful model run.

Full suites reference the exact qualified runtime DLLs, without rebuilding the
product. Besides those project references and the independently qualified Dino
hash pair, the copied harness only corrects the previously documented archived
optional-parameter helper into equivalent overloads. No numerical test is
removed or relaxed.

AMD behavior and a valid application performance comparison remain required.
The native pass does not prove every intermediate matches a double-precision
reference. No new speed ratio, production default or packing-budget selection
follows this work. Pyannote remains first on the AMD VM after the frozen e5
campaign; both owned controllers and their payloads are preserved.
