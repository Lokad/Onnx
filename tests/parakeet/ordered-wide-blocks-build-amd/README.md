# Normal AMD build of the ordered-block draft

This lane is conditional on complete wide-entry root/release qualification.
It requires the exact 423-input source draft, every parent release proof, and
the actual 422 parent inputs in the working tree. Preparation refuses an
existing output namespace and does not change root source.

Four serial jobs use the existing normal SDK 10.0.204 worker: SDK selection,
CLI restore, Release build and complete method inspection. Compare all 3,189
parent Core and 697 Data methods and flags. Permit only an eight-instruction
guarded call in RunIsolatedShortWidePackedRows and three added internal methods.
All old branch destinations, exception regions and locals must correspond
exactly after that declared insertion. Keep every existing flag, public API,
entry and arithmetic method unchanged; expect 3,192 candidate Core methods.
New guard is AggressiveInlining; new arithmetic methods are separately callable
NoInlining|AggressiveOptimization bodies with a fixed 256-term block.

Use `C:/Python313/python.exe -X utf8 -B run.py prepare`, then stage, launch,
observe, collect and `audit.py`, only after the parent release closes. Freeze
tools before staging. The offline feed, compiled inspector and parent runtime
are reused. CPU 2 computes, CPU 0 monitors. Preflight: 12 GiB available memory
and 3 GiB tmpfs. Limits: 8 GiB RSS, 1 GiB remaining memory/tmpfs, 1 GiB output
per job, 2 GiB campaign, 900 seconds per job and four hours overall. Preserve
all failures and verify the exact owners are terminal before further VM work.

A successful build proves source and compiled scope only. Both numerical
instruction modes, raw accumulation/refusal/ownership checks, native-code review
and the fixed complete-call screen must still pass before complete model and
application qualification. No benchmark ratio comes from this lane.

Nine local checker tests pass using the real parent inventory and synthetic
candidate additions. They reject changed guard arguments, fallback or exit
edges, exception boundaries, locals, stack shape, block size, other methods,
flags, Data or public API. They do not establish that the candidate compiles or
computes correctly. No build or staging has run.
