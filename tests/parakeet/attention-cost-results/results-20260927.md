# Repeated attention packing is a measured target

The scoped observation passes. Repacking the 92 attention weights without
retained preparation costs **0.817785 seconds per 20-clip corpus**, about 1.8%
of observed transcription time. Their final-row work costs only 0.080894 seconds.
This supports evaluating reuse of their prepared storage before changing a
multiplication kernel. It is an opportunity estimate, not an achieved speedup.

| Attention route | Measured calls | Complete calls, s | Packing, s | Main multiplication, s | Final row, s | Other time, s |
|---|---:|---:|---:|---:|---:|---:|
| Retained preparation accepted | 957 | 1.020955 | — | Not sampled | — | — |
| Retained preparation declined by row guard | 723 | 1.090514 | 0.109877 | 0.929299 | 0.023948 | 0.027390 |
| No retained preparation | 5,520 | 7.228941 | 0.817785 | 6.149209 | 0.080894 | 0.181054 |

Times average three measured passes. Other time includes scratch rent/return
and the unassigned complete-call remainder. Every stage has explicit start/end
timestamps; intervals do not overlap. Accepted prepared calls have only a total
clock, so their unsampled arithmetic must not be interpreted as zero.

The [fresh native comparison](../pointwise-tail-profile-results/attention-routes-20260927.md)
measures 6.131573 seconds for the corresponding 92 ORT nodes. Their current
managed main multiplication alone takes 6.149209 seconds. These are different
measurement boundaries and captures, but the proximity and directly measured
packing cost make preparation a better first target than a new arithmetic
kernel. ORT's pinned implementation prepares constant B, and all 120 current
native attention profiles omit B from runtime inputs. No new per-node native
assembly sample is claimed.

The unchanged application control takes 44.894584 seconds and the observer
45.370152 seconds: ratio 1.010593, within the prospective 1.05 ceiling. All
160 complete public transcriptions, input identities and ownership checks pass.
All 9,600 attention calls match the current weight, route and shape metadata;
7,200 measured calls contribute these totals. All 731 capture resource samples
pass, and every owner is terminal. No overhead is subtracted.

The observer changes only CPUExecutionProvider.MatMul and
Tensor<T>.RunIsolatedShortWidePackedRows. All 3,286 other Core methods, all 697
Data methods, original flags, public declarations, assembly attributes and
arithmetic leaves remain identical. Data and the application consumer are byte-
identical. Compiled review 9f8740d0 and capture closure
5ff17ed5e3e9596789bf27b27abc01584342b08f81005a4a25643b0df045b5f2 retain
the complete evidence under artifacts/parakeet-attention-cost-amd-20260927.

The selected next hypothesis is to extend the existing opt-in owned preparation
to the **92 currently unprepared square attention weights**. Replace their
original storage with the existing packed representation, preserving protection
for shared/visible weights and every existing cache entry. Keep the clone budget
and multiplication kernels fixed. The already implemented packed final-row
consumer would handle odd rows, which requires numerical qualification too.

The prediction is that per-request packing disappears for those 92 weights,
removing roughly 0.82 seconds of work per corpus before secondary effects. Admit
the change only if an independent complete application comparison achieves at
least 1% improvement, passes the original repeatability controls and has no clip
regression above 5%. Validate the exact weight census, unchanged prepared maps,
logical values, alias protections, complete outputs and resource limits first.
Reject a failed prediction without expanding into another option sweep.

The released source and BENCHMARK.md remain unchanged: Parakeet's qualified
comparison is **45.332654 versus ORT 39.232133 seconds, ratio 1.155498**. The
overall parity target remains open. [Full observations](observations-20260927.json)
and [all raw call/stage clocks](clocks-20260927.csv) accompany this report.
