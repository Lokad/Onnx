# Shorter Parakeet projection sums reduce local rounding error

On the retained Parakeet projection operands, 256-term float partial sums
reduce local RMS error by **4.75–4.82x** versus the original managed arithmetic.
They also reproduce **all 151,552 captured ORT stem values bit-for-bit** when
given ORT's own convolution outputs, across both feature sources.

This is a projection-only result. Whole-stem error still exceeds the original
`1e-4` bound because convolution error remains. The original three Windows
duration-logit failures are still open. No full-model, timing, AMD or production
qualification is claimed.

## Arithmetic and controls

The original kernel accumulates all 4,096 products in one float chain. The
prototype starts each 128-, 256- or 512-term partial sum at zero and then adds
the partials in order. It keeps the original packed weights and two-row,
32-column layout. This changes arithmetic, unlike the earlier blocked timing
probe that preserved the long accumulator.

Four captured `[1,74,4096]` inputs cross both feature sources and both
convolution engines. All use the original `[4096,1024]` weights and bias.
The 4,096-term control matches the frozen product kernel exactly on every
input. Both managed-convolution stem controls match their original captured
bits. All 160 geometry/boundary cases match an independent scalar FMA
implementation; output canaries, input immutability, 16 repeat comparisons
and held outputs pass. An independent Windows CRT `fmaf` calculation reproduces
512 sampled full-length dots from all four blocks and all four routes exactly.

Own-input double references are the previously qualified NumPy/OpenBLAS and
Torch/MKL results. Both cover every output value. The auditor independently
recomputes maximum scaled error, failure counts and RMS with scalar arithmetic.
The complete observations are retained in [observations-20260921.json](observations-20260921.json).

## Results for the selected 256-term candidate

Each array contains 75,776 values. Local error compares the computed projection
plus bias with double-precision projection of the **same actual convolution
input**. Scaled error is `abs(actual-reference) / max(1,abs(reference))`;
failure counts use the unchanged `1e-4` bound. NumPy results follow; Torch
supports the same admission verdict.

| Convolution / features | Original local RMS | Candidate local RMS | RMS reduction | Original / candidate local failures | Candidate max scaled |
|---|---:|---:|---:|---:|---:|
| Lokad / native | 2.730801e-4 | 5.661998e-5 | 4.823x | 88 / 9 | 2.403376e-4 |
| Lokad / managed | 2.711150e-4 | 5.644378e-5 | 4.803x | 101 / 9 | 2.303494e-4 |
| ORT / native | 2.720257e-4 | 5.722290e-5 | 4.754x | 90 / 4 | 1.844015e-4 |
| ORT / managed | 2.690538e-4 | 5.663741e-5 | 4.750x | 97 / 7 | 1.933150e-4 |

“Original” in this table means the original **managed projection** on each
input, including ORT-produced inputs. The last two candidate rows reproduce
the original ORT stem arrays exactly; they are not a new native execution.

All three candidate block sizes pass the fixed selection screen on every
route and both references: at least 2x lower RMS, no increase in maximum
scaled error or failure count. The predeclared rule prefers 256 when it passes,
matching the inspected native packed-block size. The 128-term variant achieves
4.93–5.04x RMS reduction and 1/5/1/4 local failures in the frozen route order;
512 achieves 3.57–3.66x and 19/21/25/23 failures. No unsuccessful result is dropped.

## Remaining error and next test

With 256-term sums, whole-stem failure counts fall from 200 to 124 on native
features and 203 to 136 on managed features when using managed convolution
inputs. They do not reach zero. The candidate therefore merits an isolated
complete-model arithmetic experiment, including the original native trajectory
fixtures and their three known failures. Passing this projection screen cannot
replace that experiment or justify broad kernel promotion.

Pyannote remains first in the AMD queue. The failed Parakeet timing comparison
is separate and is not retried by this numerical study.

## Source evidence and resource scope

At ORT1.29 commit `2e2543fbe9fae542f921d47a72d21d5a4ef0b710`,
[mlasi.h](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/mlas/lib/mlasi.h)
sets the packed reduction stride to 256.
[sgemm.cpp](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/mlas/lib/sgemm.cpp)
invokes the kernel separately for those blocks. The
[common entry macro](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/mlas/lib/amd64/FgemmKernelCommon.inc)
zeros the vector registers, and the
[FMA3 macro](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/mlas/lib/amd64/FgemmKernelFma3Common.inc)
combines each finished partial with existing C in accumulation mode. This
supports the arithmetic hypothesis; byte equality on these inputs does not
prove the installed wheel's internal dispatch.

Windows i7-14700KF, CPU2, normal .NET10.0.12. Two offline build jobs and one
numerical worker finish successfully. All 16 sampled resource observations
pass: 4 GiB preflight availability, 2 GiB RSS, 1 GiB available during work,
20 GiB free disk, 1 GiB output and 600 seconds per job. Numerical worker sampled
peak RSS is 106,913,792 bytes; build peak is 255,942,656. These sparse samples
are finite observations, not universal memory bounds. All seven recorded
process identities are terminal. No new VM load is introduced.
