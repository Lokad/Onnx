# Parakeet: inclusive constant-packing admission

The isolated adaptation of voice-branch `c679bf99` passes complete local
correctness qualification at the existing **256 MiB encoder packing cap**.
It admits reduction width 4096 through the existing shared predicate. Aggregate
caps, byte accounting, stale-weight checks, arithmetic kernels and Data behavior
are unchanged. This is not a production promotion or a speed result.

## Correctness

The old core refuses a 4096-by-32 weight at its exact 524,288-byte budget; the
candidate admits it. Tests cover neighboring widths 4095/4097, zero and
one-byte-short budgets, two independent weights, invalidation, row/column tails,
input immutability, an independent product and bitwise packed/fallback equality.
There are 204 focused passes, 12 hardware-disabled boundary passes, 3,114 full
backend passes with 93 hardware skips, and 342 tensor passes in the corrected
isolated source.

Normalized compiled instructions compare against both the archived current
baseline and the exact frozen production used by the earlier model profile.
Only `GraphPacking.FitsPackBudget` changes; all other **3,776 Core/Data methods**
match, including operands, locals, stack and exception clauses.

Twenty complete traced requests cover 213.265 seconds of audio, 1,200 decoder
calls, 1,240 graph calls, 6,080 input arrays and 4,880 output arrays. The independent
audit confirms **all 28,831,376 values match the frozen managed baseline
bit-for-bit**, including every carried decoder input and output. All twenty
traced results and twenty separate public `Transcribe` controls match the ORT
1.29 public reference. Inputs and retained outputs remain unchanged.

This does not issue a new native tensor verdict. The existing three Windows
duration-logit failures in the separate conformance fixtures remain unresolved;
their `1e-4` bound is not relaxed. No native timing is run or combined with these
diagnostic executions.

Windows i7-14700KF, logical CPU2 inherited before CLR startup, normal .NET
10.0.12. All 580 model resource samples pass the declared 12 GiB process limit:
trace peak 8,663,199,744 bytes; public peak 9,171,357,696 bytes. These finite local
observations do not qualify AMD or a larger packing budget.

## Actual bounded residency

Six fresh load-only workers compare the original and candidate admission rules.
All mappings retain correct source/clone ownership and stay within their stated
aggregate cap. The full encoder has 217 constant MatMul weights totaling
2,032 MiB.

| Encoder cap | Original retained / weights | Candidate retained / weights |
|---|---:|---:|
| 256 MiB | 256 MiB / 37 | 256 MiB / 28 |
| 512 MiB | 512 MiB / 71 | 512 MiB / 56 |
| 2,032 MiB | 1,248 MiB / 168 | 2,032 MiB / 217 |

At 256 MiB, the candidate retains six `[4096,1024]`, six `[1024,4096]` and
sixteen `[1024,1024]` weights. New eligibility changes which weights occupy
the fixed cap; fewer matrices does not mean less retained memory. At 2,032 MiB,
all 49 previously excluded `[4096,1024]` matrices are present. That configuration
adds 1,776 MiB of retained copies versus the current public default.

All 36 census resource samples pass; the largest sampled load-only RSS is
4,457,439,232 bytes. **Budgets above 256 MiB have no inference, complete-application
memory or speed qualification yet.** The next decision is explicit budget
qualification followed by a valid complete-application comparison. The earlier
rejected kernel timing grids provide no substitute.

## Retained failures and evidence

The initial full suite failed the old `4096 => false` predicate assertion.
The successor updates it and adds `4097 => false`. Its tensor scan then found
default parameters in the new test helper and an existing archived Whisper test
helper. Explicit overloads correct those helpers in the isolated source without
changing runtime binaries. The original archived Whisper tool stays untouched.
One resumption incorrectly expected Data in the Core-only tensor test output;
it stopped before tests and its failure remains recorded.

The first model launch stopped on the no-child-process guard before creating
any trace output. Child details were not recorded, so its cause is unassigned.
The successful successor keeps identical consumer bytes, uses detached startup
and records children before checking the guard. Original and successor workers
are terminal. All failures, including two early attempts before the first
failure receipt was ready, remain distinct from the passing qualification.
