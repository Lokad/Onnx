# One positional-copy prototype is ready for full Parakeet qualification

The isolated prototype passes **395 tensor tests in each instruction mode**,
with no skips. Its compiled review proves all **3,253 original Core methods**,
their implementation flags and helper guards unchanged. The only addition is
`TensorSlice<T>.ToDenseTensor`: use the existing guarded contiguous-copy helper
when eligible, otherwise call the original base conversion. The override's
effective signature is unchanged from the previously inherited method.

This addresses a measured discrepancy with the exact installed ORT: all 24
positional projections share one sliced constant. ORT materializes that slice
once; Lokad materializes its view before each multiplication. The unchanged
product's elementwise conversions cost 2.409943 seconds per twenty-clip corpus.
The faster-helper component comparison remains **unadmitted** because 13 short
per-clip repeatability controls failed. No component threshold was changed.

The prototype still makes independently owned copies; it does not introduce
shared graph materialization or change multiplication, packing, cache budgets,
row guards or compiler options. All 19 actual positional lengths, exact float
bits, offset backing windows, cropped axes, independent ownership, held outputs,
fallback layouts, derived behavior and a MatMul caller are covered.

Core `49c3a958` was built once. Product build warnings remain the same two existing
CS8604 warnings in Zzz.WideProjectionEntry.cs. Compiled review `349ae125` passes;
the final test consumer `a17057a3` was built without warnings. Joint tensor
closure `a4d86d05` joins the successful ordinary and disabled suites, requiring
the identical 395 case names and consumed Core hash. The disabled suite observes
Avx512F.IsSupported false and Fma.IsSupported true.

All qualification incidents remain retained. The first assembly checker used
an open constructed generic type's FullName instead of its generic definition;
only that checker was rebuilt. The first suite passed 394 cases and failed a new
reversed-layout oracle: enumeration is [2,4,3,5], while backing storage is
[2,3,4,5]. Only the test changed, adding explicit checks of both. Its ordinary
suite then passed 395. The attempted disabled suite caught an ineffective
DOTNET_EnableAVX512F flag; only that missing mode ran again with the established
release flag DOTNET_EnableAVX512=0. No successful ordinary suite or product build
was repeated. Original failed collections and all resource samples remain.

**No application gain is measured or integrated.** Root source and BENCHMARK.md
still describe source `dddb60ef`: 64.705703 seconds versus ORT 39.636305, ratio 1.632486.
Next are complete native/public Parakeet checks, matched positional-group
attribution and the original fresh current/candidate/ORT application comparison.
Admission still requires at least 3% corpus improvement, no clip more than 5%
slower, all repeatability controls and subsequent full release regression gates.
