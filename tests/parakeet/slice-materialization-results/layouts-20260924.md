# Actual Parakeet slice layouts confirm the copying hypothesis

All **1,920 observed attention slices** qualify for contiguous bulk copying:
24 layers × twenty clips × four original corpus passes. Every parent is a
concrete dense, row-major float tensor; every slice has unit steps. All eight
retained regions fit the parent's memory window. All **80 complete public
requests** match the selected release exactly, including token/frame/duration
decisions, repeats, input immutability and held-output ownership.

This resolves the layout uncertainty in the
[matched ORT diagnosis](../managed-phase-results/results-20260924.md).
The measured Slice→Reshape pair cost was 2.962s versus ORT's 0.024s. This capture
establishes the applicable layout, not a speedup. Its diagnostic corpus time
was 73.540392s. The qualified release remains 1.864× ORT.

At each actual encoded length T, the parent is `[1,8,2T,T]`. Slice removes
the first row of each attention head to give `[1,8,2T-1,T]`, then Reshape returns
`[1,8,T,2T-1]`. The copy must retain `(2T-1)*T` elements per head, starting at
`head*2*T*T + T` relative to the parent's memory window. There are gaps of T
elements between retained regions. A single flat alias would be incorrect.

All nineteen corpus lengths, from 51 to 225, appear in the capture. Length 156
occurs in two clips. All observed arrays have offset zero; the proposed contract
tests also exercise nonzero memory offsets, which the public tensor API permits.
Neither arrays nor tensors are retained by the observer.

An isolated Core adds one observation call before `TensorSlice.Reshape`'s
original body. Compiled review confirms all **3,188 other Core methods**, all
**161 other consumer methods**, original flags and public surface are unchanged.
The original Reshape instructions remain exact after the added call. Data stays
byte-identical. The consumer retains its original four passes and correctness
checks, saving scalar records after its original request clock.
