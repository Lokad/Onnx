# Dense mixed-mask selection: compiled scope

The isolated AMD build passes its compiled-scope checks. It changes only the
float arm of `CPUExecutionProvider.Where` and adds two internal methods in
`DenseScalarWhere`. The selected root remains source `81f75c38`.
This report establishes build scope; it does not establish numerical correctness
or a performance gain.

The provider keeps its existing validation order and all nonfloat branches.
Its body grows from 196 to 229 IL instructions; the float arm grows from 15 to 48.
The 4,096-element minimum and scalar true operand guard precede the helper call.
Generic `Tensor<T>.Where` is unchanged, as are 3,188 other existing Core methods
and all 697 Data methods. Existing implementation flags and public interfaces
are exact. Seven adversarial scope-checker tests passed before execution.

The candidate has 3,191 Core methods. `Try` has 205 IL instructions and
`SelectMixed` has 238; both have NoInlining/AggressiveOptimization flags (520).
The scope audit admits these specific signatures but deliberately does not
certify the new helper bodies' behavior. Mixed masks now enter a dense run
selector; unsupported layouts and shapes keep the generic fallback.

Four AMD jobs completed: SDK check, offline restore, Release CLI build and
instruction inventory. All 74 resource observations pass; peak RSS is
504,287,232 bytes. Owner 895615 / birth 1790216062.92 is terminal with code 0.
SDK 10.0.204, runtime 10.0.8, compute CPU2 and monitor CPU0 were retained.
