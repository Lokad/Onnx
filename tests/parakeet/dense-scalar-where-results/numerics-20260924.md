# Dense mixed-mask selection: numerical and generated-code qualification

The new scalar selection kernel passes numerical qualification through both
`Tensor<T>.Where` and `CPUExecutionProvider.Where`. It is an isolated candidate;
no performance result or release integration is admitted by this report.
The selected release remains Core `672e5f30` / Data `065b7a7f`.

Four numerical workers exercise 235 cases at each boundary, using selected and
candidate assemblies in ordinary and AVX512-disabled modes. All **30,403,936
values** match the independent coordinate oracle and the selected product's
stored bits. Fifteen cases retain their expected error behavior; twenty separate
provider contracts per worker preserve option validation, failure metadata and
validation order. Full input stores, offsets, held results, mutated inputs and
independently owned outputs pass. All original 131 reference output and mutated
output hashes remain exact.

The census adds 32 run layouts across ranks 1–8 to the preceding 203 cases.
It covers full masks, scalar last axes, trailing masks and alternating broadcast
axes, with first/last/alternating truth patterns. NumPy independently verifies
captured inputs, raw Boolean bytes and the 32 new layouts as integer float bits.
Zero, negative zero, infinities, NaN payloads and subnormal values are preserved.
The 0/1/2/255 Boolean cases retain zero/nonzero semantics.

The helper admits 152 cases. The provider's unchanged 4,096-element guard
attempts 123 cases and admits 95; other types and unsupported layouts retain
fallbacks. The two modes and two boundaries produce 608 numerical helper
admissions. Every valid provider invocation has the expected ordered profiler
stages: one validation on helper success, four normally, five on refusal after
an attempt. Profiling durations are not comparative measurements.

Nine AMD jobs finish successfully under terminal owner 896466 / birth
1790216810.3. All 133 resource observations pass, with peak RSS 329,285,632 bytes.
One consumer, SHA-256 `7e55f2bf4b5fd2fc33c0c71a24663b2afc6597fea76b78f54286ab96d8317ea7`,
serves both products. Numerical tools were frozen at `b3a9af85`.

## Generated code

Two separate ordinary workers call each of the 220 valid cases 81 times through
each boundary, with profiling disabled. All 56 emitted bodies are retained and
parsed completely: 29 selected and 27 candidate. Every named branch label
resolves; complete call lists, metadata and a generic float body diff are in
[the machine-readable review](codegen-review-20260924.json).

`Try` preserves null, exact class, layout, rank and shape refusals before mask
scanning or allocation. It scans for zero/nonzero truth, allocates a fresh result,
then calls copy, fill or mixed selection. The mixed body clears its stack
coordinates, coalesces a trailing run, and advances outer coordinates with
integer carries. Its contiguous inner loop checks the raw mask byte and moves
the selected float bits. It has no allocation, division, broadcast/GetValue call
or floating-point arithmetic. Scalar condition runs call copy or fill.

Both generic float entries retain 23 profiled inlinees, zero external
`BroadcastShape` calls and four integer divisions. Their layouts differ; native
identity is not claimed. The candidate provider retains the 4,096/scalar guards,
all nine dtype fallbacks and owned success metadata. This short diagnostic emits
only its Tier0 provider entry; the selected provider also emits instrumented Tier0
and Tier1. These observations do not establish compilation tiers in a future
timed process or explain the earlier rejected comparison causally.
