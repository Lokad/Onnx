The original clocks narrow the next diagnosis. Across all consecutive 60-round
blocks, the unmapped slowdown is persistent in both candidate processes, including
warmup; it is not explained by a few measured outliers. Narrow candidate controls
settle at different process-specific plateaus early in warmup. Scalar and Simd
means and fallback allocation remain effectively unchanged. These observations
do not establish the cause or dismiss any failed gate.

One plausible cause for the unmapped result is the fixed round-robin sequence:
the preceding mapped call reads the candidate's separate 20,986,880-byte packed
buffer, whereas current reads the same original B that the unmapped call then
reuses. That can change cache residency. Competing explanations include changed
JIT code or dispatch cost. The existing seven-call batch clock cannot distinguish
a slow first call from seven slower calls. A bounded per-call observation can
resolve that ambiguity before another product edit. Narrow process differences
remain a separate unresolved control; no longer warmup, trimmed score or new
kernel variant is justified by the current evidence.
