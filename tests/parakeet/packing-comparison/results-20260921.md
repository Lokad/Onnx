# Parakeet packing comparison: stopped at the available-memory guard

The prospective eight-process application comparison stopped during its first
512 MiB candidate worker. Available workstation RAM fell below the unchanged
1 GiB guard. **No candidate speedup, candidate/ORT ratio or selection is valid.**
The original Microsoft ORT benchmark tables remain unchanged.

## Retained execution

The fixed order was production, 512 MiB, 2,032 MiB, ORT, ORT, 2,032 MiB,
512 MiB, production. Each worker was to run twenty clips, one warmup pass and
three measured passes: 640 requests across eight fresh processes. Runtime,
consumers, model/corpus identities and control thresholds were frozen before
launch in [protocol.md](protocol.md).

| Worker | Exit | Completed requests | Warmup / measured | Resource samples | Peak RSS, bytes |
|---|---:|---:|---:|---:|---:|
| First production | 0 | 80 / 80 | 20 / 60 | 958 | 10,318,372,864 |
| First 512 MiB candidate | 15, terminated by supervisor | 56 / 80 | 20 / 36 | 766 | 12,087,197,696 |

All 136 retained request records independently pass the original public-output
reference, input hash, per-request ownership, clock and repeat checks. The
production worker also passes the original complete-worker validator and its
final held-output check. The stopped candidate has no final `result.json`, so
its final held-output check and completed application verdict are unavailable.
No 2,032 MiB or ORT worker started. The remaining six workers were not launched.

At the failing sample, 207.758 seconds into the candidate worker, available RAM
was **1,041,678,336 bytes**, below 1,073,741,824. Its RSS at that instant was
9,923,104,768 bytes. Its earlier peak also remained below the 12 GiB RSS limit.
Time, disk, output size and CPU-affinity checks passed in every sample. Both
workers had passed the 14 GiB available-memory preflight. The full record
contains 1,724 resource samples, including the one failing availability check.

The monitor records whole-machine availability and the owned worker's memory,
not concurrent per-process memory changes. The cause of the additional memory
pressure is therefore **unassigned**. The unrelated workstation process was
preserved. The supervisor terminated only its recorded candidate process;
both workers, the runner and the finisher are confirmed terminal by PID and
creation time.

## Consequence

The [separate larger-budget qualification](../packing-budgets/results-20260921.md)
still establishes complete regression coverage for both configurations. It
does not establish that repeated benchmark passes satisfy the resource limit
under every workstation load. All three existing native numerical failures
remain open.

This attempt supplies no complete control pairs and no fresh native timing.
There is no budget selected for AMD, no production promotion and no unchanged
local timing retry. A future performance experiment needs an isolated resource
envelope and a new prospective protocol. Pyannote retains first use of the AMD
audio lane after the existing e5 controller releases it.
