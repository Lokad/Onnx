# Parakeet partial sums clear the three Windows native failures

The isolated arithmetic candidate passes **all 784 arrays / 3,090,494 values**
in the original complete Parakeet native conformance fixtures. The unchanged
`1e-4` bound now has **zero failures**, versus three in frozen production.
All twenty separate public corpus requests also pass.

This qualifies these Windows fixtures for the candidate, not the current
production runtime. AMD behavior, affected-model qualification and performance
remain separate. No speed claim or production promotion follows this result.

## Change and scope

Core `1858c242` adds 256-term partial sums behind the two existing packed row
kernels. Admission requires FMA, a reduction of at least 1,024 terms and an
output width divisible by 32. Each completed partial is added to existing C,
preserving nonzero destination accumulation. The helper handles pairs of rows
and a final single row. Short reductions and column tails use the original
kernels. Packing admission, weight budgets, TensorOps dispatch and Data stay
unchanged.

The compiled-instruction comparison permits exactly two changed methods and
one added helper. **3,084 other Core methods and all 691 Data methods** match
the frozen production instructions. The original `TranscribeReplay.dll` and
`AudioBenchmark.dll` are byte-identical; neither consumer is rebuilt or relaxed.

## Complete native and public results

Both engines retain their own carried decoder trajectories. Original fixtures
cover English, French, JFK, token/frame limits, silence and repeat, plus six
invalid/cancelled requests and recovery. Public decisions, caller inputs and
held outputs pass. The original independent Python auditor recomputes every
native array comparison and rechecks the retained baseline failures.

## Kernel and resource checks

All **416 geometry cases** pass: 64 admitted cases match independent scalar
partial-sum arithmetic on nonzero C, while 352 fallback cases match original
frozen kernel bits. Inputs, packed weights and output canaries are preserved.
Cases include both row kernels and boundaries around the 1,024-term admission
and 256-term blocks. Four actual captured projections reproduce the preceding
qualified arithmetic. Four hardware-disabled refusal/public checks pass.

Windows i7-14700KF, CPU2, normal .NET10.0.12. Native references remain Microsoft
ORT1.29.0 with original one-thread CPU settings. All nine build/probe jobs and
both model workers complete. Their 462 sampled resource observations pass.
Native replay peaks at 6,498,172,928 bytes RSS under 8 GiB; public corpus peaks
at 9,247,735,808 under 12 GiB. Preflight availability is 10/14 GiB respectively;
both retain 1 GiB available RAM, 20 GiB free disk, 1 GiB output and 1,200-second
guards. All nineteen recorded process identities are terminal.

The full repository suites ran against these exact binaries: **3,099 backend
tests pass, two fail and 93 skip; all 342 tensor tests pass.** The failures are:

- `PackedBumpMatchesPacked2Bitwise`: the documented bitwise relationship to
  the old kernel breaks on `[126,1536] × [1536,384]`.
- `DinoV3Outputs_MatchFrozenBitHash`: the complete-output hash changes. The
  existing mean/spot checks pass, but those do not qualify every changed value.

These failures prevent promotion of this implementation. Test expectations and
frozen hashes were not relaxed. The test harness references the exact qualified
Core/Data/dependencies; it does not rebuild them. Only three project references
and a known archived optional-parameter helper in a scanned, uncompiled test
tool copy were adjusted. The original helper and all historical evidence stay
unchanged.

The first suite attempt stopped at its declared 2 GiB process-tree guard at
2,153,668,608 bytes, before a backend result. Tensor tests had not started.
The explicit successor reused unchanged binaries under the previously
established 8 GiB suite limit and retained that stop. The completed backend and
tensor runs pass all 233 resource samples, with peak RSS 4,157,046,784 bytes.
The backend failure is retained; the tensor suite ran separately afterward.

## Limits and follow-up

Passing the native output fixtures does not prove that every intermediate
matches an independent double-precision reference. The earlier whole-stem
diagnostic still records inherited convolution error. This candidate also
changes shared kernels, so affected pyannote/e5 behavior and any performance
tradeoff must be checked before promotion. The next implementation should
preserve the old raw kernels and select new arithmetic through the tensor
dispatcher. Every changed DinoV3 output must be independently qualified before
any additional frozen hash is accepted. Narrowing admission merely to evade
these tests or loosening the existing bounds would not resolve the issue.
Pyannote remains first on the AMD
VM after the frozen e5 campaign; neither live controller is changed.
