# Parakeet: complete inference with larger bounded weight caches

Both isolated configurations—**512 MiB and 2,032 MiB** of encoder packing—pass
complete local regression and memory qualification. Every captured value keeps
the original managed bits. The three existing Microsoft ORT numerical failures
are reproduced unchanged. This result does not establish a speed gain or AMD
qualification.

## Changes and coverage

Both variants use the exact qualified inclusive-admission Core `737e9013`.
Each changes only the encoder-budget constant in `ParakeetTranscriber`'s
constructor. Compiled instruction comparison confirms the single constant
change and identical instructions in every other Core/Data method. The public
API, all arithmetic kernels, runtime defaults and production source stay unchanged.

Each budget runs three fresh sequential processes on Windows i7-14700KF,
logical CPU2, normal .NET 10.0.12:

- Twenty complete traced requests: 1,240 graph calls, 6,080 input arrays,
  4,880 output arrays and **28,831,376 values**, all bit-identical to the frozen
  managed baseline. This includes all 1,200 carried decoder calls.
- Twenty separate public transcriptions: all match the original ORT 1.29
  text, tokens, frames, durations, stop reasons and call counts.
- The original native conformance consumer: all **784 arrays / 3,090,494 values**
  match the frozen production bytes. English, French, JFK, token/frame limits,
  silence, repeat, invalid/cancelled requests and recovery retain their contracts.

Inputs and held outputs remain unchanged. Each native consumer exits with code 1,
as required by its numerical verdict. The independent auditor reproduces the
duration-zero logit failure at step 26, index 8193, for English, its frame-limit
case and its repeat. Maximum scaled error stays **0.0002321004867553711** at the
unchanged `1e-4` bound. Regression passes; native numerical parity does not.

The larger configuration retains all 217 encoder constant MatMul weights.
Actual graph accounting matches each declared cap exactly. Its public peak is
about **11.14 GiB**, versus a common 12 GiB process limit. These are sampled,
finite observations, not a universal memory bound or a controlled memory delta.

All **1,277 inference resource samples** pass: 14 GiB available RAM before
launch, 12 GiB process RSS, 1 GiB available RAM during execution, 20 GiB free disk,
1 GiB output and 1,200 seconds per worker. Initial preparation waited for local
RAM to become available; the unrelated workstation process was preserved.
All six inference workers and their supervisor are terminal.
