# Optimized pyannote versus Microsoft ORT on Windows

The qualified isolated candidate takes **12.446 seconds versus ORT's 6.584
seconds** for the complete 30-second dialogue: **1.890× native latency**.
All 64 public requests pass, with every warmup and measured call retained.
This is a fresh matched Windows comparison. AMD execution and production
promotion remain pending; the result does not establish parity.

## Protocol and scope

Windows i7-14700KF, logical CPU2, .NET 10.0.12, Microsoft ONNX Runtime 1.29.0.
Four fresh processes run candidate, ORT, ORT, candidate. Each runs one complete
four-case warmup and three measured passes: 48 measured and 16 warmup requests.
Affinity is set before runtime startup. Managed execution uses normal runtime
settings. ORT uses CPUExecutionProvider, one intra-op and inter-op thread,
sequential execution, all graph optimizations and no spinning. Torch and the
other numerical libraries use one thread.

Both engines start from the same PCM and FP32 graph files. Timers include
frontend features, inference, automatic clustering and owned output construction.
Model loading, file access and external validation are excluded. The native
application combines ORT segmentation/embedding/projection graphs with the
original pinned Torch/NumPy/SciPy frontend, pooling and clustering code.

The candidate is the previously qualified `469cb2d6` core: spatial convolution
panels, contiguous copies and ordered LSTM output lanes. Data assembly `e7fe1668`
and the original public `AudioBenchmark` consumer retain their exact bytes.
The new AVX-512 convolution-row successor is not used here.

## Correctness and resources

The independent public-result auditor checks every field, timeline structure,
PCM identity and clock interval. All 64 calls pass at the unchanged centroid
scaled `1e-4` bound; maximum error is `3.0249357223510742e-6`. Both consumers
also check repeated output stability, retained result ownership and input
preservation through every request. The managed worker verifies that no native
ORT module is loaded.

This public application gate does not replace full graph numerical evidence
or erase known silence-tensor failures. The exact candidate's separate
[graph qualification](../lstm-output-lanes/results-20260921.md),
[natural meetings](../optimized-meetings/results-20260921.md) and
[Parakeet regression](../optimized-parakeet/results-20260921.md) retain those
scopes and limitations.

All **382** resource samples pass. Peak sampled RSS is **1,227,952,128 bytes**
for candidate and **620,220,416 bytes** for ORT. Limits are 1,800 seconds per
worker, 8 GiB RSS, 1 GiB available RAM, 10 GiB preflight available RAM and 20 GiB
free disk. All four workers and their supervisor are terminal. This campaign
ran no inference on the AMD VM.
