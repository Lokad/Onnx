# Default-gate generated code on AMD

The isolated M26 helper calls MathF activations directly in all four execution
modes. Its optimized body retains three Exp calls and two Tanh calls, in the
original order, with three scalar multiplies and sixteen scalar additions.
There are no activation delegate calls, allocation helpers or fused operations
in this body. Scalar values still spill across activation calls. This is a
code-generation result; it does not establish a latency reduction.

The helper is670 bytes in ordinary, AVX512-disabled and explicit SIMD-only
modes, and679 bytes with hardware intrinsics disabled. The unchanged generic
source loop remains available for other activations, clipping, peepholes,
coupled gates and absent bias. Focused differential tests exercise this loop.
The diagnostic consumer and both products are reused without rebuilding.

All eight selected/candidate replay processes pass192 complete calls,
576 outputs and29,048,832 values. Maximum scaled native error remains
1.591294694046004e-5. Readonly operands, held owned outputs and exact scratch
pass. All95 resource observations pass, peak RSS137,150,464 bytes; every
recorded owner is terminal.

The original local auditor rejected an interleaved JIT log: the complete
670-byte gate body was followed by a deferred924-byte projection body whose
header had appeared earlier. Its failure and every original fragment remain
in the artifact. The separate v2 auditor accepts the gate prefix only after
its entire instruction/basic-block/constants text exactly matches the clean
670-byte body from the ordinary-mode process. Eight unique basic blocks and
the following fragment's reset/footer are also checked. No worker was rerun.
