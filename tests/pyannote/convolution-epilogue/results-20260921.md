## Source comparison

The qualified candidate's `TensorOps.ConvPool.cs` implements
`RunTiledBatchFloat` with a temporary matrix output, followed by a per-element
copy into final output storage and an optional bias addition. All36layers
exercise the bias-present case here. The earlier complete-request sample
attributes9.85–10.60%to the tiled caller, but inlined helpers can contribute to
that leaf. The trace does not isolate the copy/bias loop's cost. The source
expresses scalar operations; this review does not establish emitted JIT code.

Microsoft ORT1.29
[convolve.cpp](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/mlas/lib/convolve.cpp)
passes the final output's row stride to its matrix routine and applies activation
and optional bias to each completed output segment. Its
[activate.cpp](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/mlas/lib/activate.cpp)
has four-float vector load/add/activation/store operations plus a scalar tail;
the identity-without-bias specialization is empty. This establishes a source
design, not the installed wheel's actual dispatch or a measured advantage.

Two implementation ideas follow for later testing: vectorize the independent
bias-and-copy operations while preserving scalar/SIMD policies, or add a packed
matrix consumer with an explicit destination row stride to avoid the temporary
output copy. The second would require a new carefully qualified kernel.
Preserve the ascending matrix reduction, bias addition order, tails, groups,
padding, mutable weights, output guards, signed zeros and non-finite behavior.
Neither idea is implemented or admitted by this census. The current full
application comparison takes precedence over new inference experiments.
