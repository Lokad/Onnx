# Wider LSTM code and fallback dispatch verified on AMD

The exact qualified candidate emits sixteen-lane AVX512 projections in
ordinary mode. Its complete replay outputs remain exact. AVX512-disabled
and explicit SIMD-only modes use the existing eight-lane portable projections;
hardware-disabled execution uses no panel projection helper. This diagnostic
result admits the candidate to the fixed component timing screen, not to
integration or a new application/ORT performance claim.

The optimized single-row wide loop has four independent accumulators,
four multiplies and four adds per reduction input. The four-row loop has
eight accumulators, two shared weight loads, four broadcasts, eight multiplies
and eight adds. Each visits reduction inputs in increasing order. Neither
wide reduction loop contains vector spills or scalar stack references.
No fused vector multiply-add appears in the optimized projection bodies.

The retained portable tail inside the wide four-row helper has ten scalar
stack references in its full Tier1 loop, versus none in the original full
Tier1 portable loop. It has no vector spills. The actual captured 512-output
graphs fill the wide tiles. Full Tier1 method sizes are 640 bytes for the
wide single-row helper and 1,901 for the wide row helper, versus 435 and 1,765
for the portable helpers. All 170 emitted listings, including Tier0, OSR and
interleaved fragments, remain in the evidence; no tier is discarded.

wide or portable calls. The qualified source/compiled inventory additionally
requires actual Vector512/AVX512 support when creating that flag. The SIMD-only
consumer explicitly selects TensorExecutionOptions.Simd; its flag remains
false. These caller and source checks support the observed fallback behavior;
absence of a helper listing alone is not treated as dispatch proof.
