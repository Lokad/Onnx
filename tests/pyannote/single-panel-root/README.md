# Conditional root integration of single-panel convolution

Run only after the complete single-panel-amd-v2 campaign finishes and its
independent audit reports `performance.admitted=true`. The tools verify that
closed evidence, the actual terminal controller, every original model/meeting
and speed gate, and the exact qualified candidate before changing any source.

From repository root, use `C:/Python313/python.exe -X utf8 -B` with `run.py`, then
`audit.py` after successful termination. Output is
`artifacts/pyannote-single-panel-root-20260922`; existing output is refused.

The frozen four-file patch adds the checked wrapper, unchanged arithmetic kernel
and focused tests, plus the tiled caller change. Normal CLI/backend/tensor builds
must match all 3,113 Core / 697 Data methods and public declarations of the measured
Core `1279b4b6` / Data `4e602d9f`. Full Windows suites require 3,313 backend passes
with 93 existing skips and 343 tensor passes.

The actual root Core must be present in the NuGet package, retaining its sole
Google.Protobuf 3.33.5 dependency. The independent PackageReference consumer must
retain all public operator/import/ownership checks and 33,216 tiled values. It
also checks 10,240 narrow-convolution values and exactly 327,680 scratch bytes,
proving that the packaged narrow route avoids another packed rental.

Build preflight requires 8 GiB available; inference requires 10 GiB. Owned RSS
stays below 8 GiB, each worker below 900 seconds, with 1 GiB output, 1 GiB available
memory and 20 GiB free disk guards. CPU2 is inherited before CLR; monitor CPU0.
All .NET commands disable the terminal logger. Final auditing verifies actual
termination and freezes source snapshots. Timing belongs to the measured binary;
method equivalence does not create a separate score for the root rebuild.

A failed application gate prohibits this integration. The earlier direct-root
tools remain unexecuted because their candidate failed admission. These tools
never push or publish a package.
