# ORT's optimized Pyannote embedding graph uses blocked channels on Windows

The local ORT 1.29.0 session rewrites **all 36 embedding convolutions** to
`com.microsoft.nchwc::Conv`. Sixteen have a fused residual-sum input and 33 have
a ReLU attribute. There is **one ReorderOutput and no ReorderInput**: the first
convolution accepts the single-channel input directly, and the following
convolutions retain the blocked layout. This is a distinct architecture lead
for the remaining Pyannote gap.

| Model | Original top-level nodes | Optimized top-level nodes | Blocked convolutions |
|---|---:|---:|---:|
| WeSpeaker embedding | 111 | 50 | 36 |
| Segmentation | 144 | 50 | 0 |

This inspection constructs and serializes sessions; **it executes no inference**.
It establishes the local optimized graph, with no AMD dispatch, numerical or
performance claim. Node counts exclude subgraphs. Segmentation retains its two
ordinary convolutions and four LSTMs; it requires a separate performance strategy.

The pinned ORT source is revision
`2e2543fbe9fae542f921d47a72d21d5a4ef0b710`. Its
[NCHWc transformer](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/optimizer/nchwc_transformer.cc)
requires constant float convolution weights, checks channel/group geometry,
reorders filters and preserves compatible blocked connections. The
[operator implementation](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/contrib_ops/cpu/nchwc_ops.cc)
calls `MlasNchwcConv`, with optional bias and residual accumulation. In
[snchwc.cpp](https://github.com/microsoft/onnxruntime/blob/2e2543fbe9fae542f921d47a72d21d5a4ef0b710/onnxruntime/core/mlas/lib/snchwc.cpp),
MLAS selects blocked spatial, pointwise, depthwise or small-channel convolution
according to geometry. Its blocked spatial implementation traverses input-channel
blocks and output rows directly, calling the platform convolution kernel.

Lokad's selected `TensorOps.ConvPool.cs` instead expands bounded spatial patches,
then uses `ConvDirectOutput.Multiply` with packed matrix kernels. Its narrow
patch optimization avoids redundant packing, while ordinary patches still
require expansion. `CPUExecutionProvider.ConvRelu` applies ReLU afterward to
the fresh output. These source differences identify work to investigate; they
do not quantify the remaining gap or justify an immediate layout rewrite.
