# Complete-request pyannote sampled thread attribution

Two independent captures identify the same dominant leaf: the existing
`mm_unsafe_vectorized_intrinsics_2x4packed_bump` matrix kernel accounts for
**55.05% and 57.17%** of selected full-request thread time. The tiled convolution
caller accounts for another **10.60% and 9.85%**. This supports investigating
matrix computation after the qualified allocation reduction failed to establish
a latency improvement. It is not a new speedup or Microsoft ORT parity result.

Each capture includes three complete measured 30-second requests and three
calls to each ten-second crop. Exclusive leaves reconcile with their selected
total. Inclusive callers overlap and must not be added. Inlining can charge
helper work to its caller: the tiled caller's share does not prove that its
bias/copy loop consumes that entire share. The differing LSTM split also
discourages attributing precision to individual smaller methods.

## Scope, coverage and overhead

The Windows i7-14700KF target runs on logical CPU2 with normal .NET10.0.12
startup and no runtime overrides or forced collections. The collector runs on
CPU0. Pinned dotnet-trace10.0.745401 attaches to the verified owned process only
after four warmups. An enabled EventSource and release barrier precede the
measured requests. Four non-inlined wrappers identify the public API intervals;
validation, loading, serialization and warmup are outside them.

The [Microsoft tool documentation](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/dotnet-trace)
distinguishes sampled managed thread time from kernel CPU sampling. The exporter
calls one synthetic bucket `CPU_TIME`; that label is retained, not interpreted
as measured CPU usage. Process user/system counters are measured separately.
Native/kernel frames are not established by this diagnostic.

Speedscope and Chromium agree on every event: 11,002 in A and 11,444 in B.
Each fixture has exactly three observed marker intervals on the target OS
thread. Selected full-request totals versus actual wall intervals are
42.389605/42.396963 seconds and 39.021255/39.017069 seconds. Across all fixtures,
coverage ratios range from 0.964843 to 1.009802. Process CPU totals for the full
request are separately 42.093750 and 38.656250 seconds. Outside-marker exported
time is 0.352476 and 0.302902 seconds. No event rounding adjustments were needed.
