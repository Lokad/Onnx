## Retained failures and corrections

The initial inventory rejected apparent removals caused by compiler-generated
symbol numbering. The explicit review successor proves 197 method renames and
217 symbol mappings bijectively, then compares complete instruction bodies.
Seven normalizer tests pass; user literals and numeric constants are preserved.
The original rejection remains closed as
`b52ca1fe7ed0edf06094708ae581c1224cd659a1903ec6844ac58af76856b901`.

Two test assumptions required correction. Runtime initializer overrides require
`useInitializers:false`. Replacing an initializer safely falls back until explicit
preparation refreshes its clone. The intermediate run passed 30/31 tests; its
failure asserted immediate clone replacement after output already matched.
The final focused consumer calls `Prepare()` before that clone assertion and
checks output again. Product sources, binaries and numerical gates never changed.
Eventual integration must use that corrected test source.

The first broad regression command exited 1 before producing a TRX; its log said
`--no-build --no-restore` were ignored. The project-based successor uses the
repository's established command and retains the failed invocation separately.
That run passed all 3,313 existing backend tests (93 original skips) and 342/343
tensor tests. The sole tensor failure found optional parameters in new test
helpers, forbidden by the repository's unchanged source rule. A fresh normal
source copy replaced them with explicit overloads. Its first backend build found
that target-typed `new()` in one rewritten helper selected the `object` execution
overload. The final explicit successor spells out `Dictionary<string, ITensor>`.
Both failures remain retained. The complete combined suites now pass; no product
source or numerical assertion changed.
