## Adaptation

The actual segmentation graph has four bidirectional LSTMs with hidden size 128.
Their input widths are 60/256/256/256; each has 512 gate outputs. The prototype
adapts the independent-output panel idea from voice `03af0bf`/`c762e7b`.
Each vector lane computes one complete output, visiting inputs in increasing
order. It uses separate multiplication and addition, matching master's scalar
projection rather than importing the branch's FMA arithmetic. There is no
horizontal reduction, gate approximation or forced JIT setting.

The provider prepares transposed input/recurrent weight panels once per call
in one checked, accounted ArrayPool rental and returns it on exit. No prepared
cache is introduced, so subsequent calls see weight mutations. The existing
gate loop, biases, peepholes, clipping, directions, sequence-length handling
and returned tensors remain unchanged. Four portable accumulator vectors
process independent outputs; scalar tails retain the same reduction order.

The new path requires SIMD, hardware vector support, sequence length at least 8
and hidden size 16–128. Other cases retain the existing scalar projections.
This admission is a prototype cost choice; application gains are demonstrated
for the actual hidden-size-128 pyannote graph. Larger recurrent models require
their own performance work. Main source/defaults are not changed.

Product differences from the copy baseline are confined to wiring in
`CPUExecutionProvider.Recurrent.cs` and the new private helper file
`CPUExecutionProvider.LstmPanels.cs`. Convolution and matrix multiplication code
remain unchanged. Model files, the Data assembly and comparison consumer retain
their exact qualified bytes.
