# Pyannote convolution output allocation census

The embedding graph's 36 convolution outputs total **159,764,480 bytes** of
float payload for each captured ten-second input. The exact qualified Lokad
source allocates those outputs outside its reusable execution pool, including
the 17 fused ConvRelu nodes. This makes output allocation a concrete target
for a separate prototype. No inference or timing run was added for this census.

| Output shape | Convolutions | Bytes per output | Combined bytes |
|---|---:|---:|---:|
| 1 × 32 × 80 × 998 | 7 | 10,219,520 | 71,536,640 |
| 1 × 64 × 40 × 499 | 9 | 5,109,760 | 45,987,840 |
| 1 × 128 × 20 × 250 | 13 | 2,560,000 | 33,280,000 |
| 1 × 256 × 10 × 125 | 7 | 1,280,000 | 8,960,000 |

All three captured dialogue crops have input shape `[1, 998, 80]` and the
same output-size census. ONNX metadata shape inference is checked independently
using each convolution's input, weight, padding, stride and dilation dimensions.
The final graph output shape `[1, 2560, 125]` matches the retained fixture.
Every convolution name appears exactly once in each original executed graph
trace: 19 Conv and 17 ConvRelu nodes.

The [context-reuse probe](../context-reuse-probe/results-20260921.md) measured
166,860,713 and 166,867,712 mean allocated bytes per repeated embedding call
in the two process orders. The static convolution output payload is 95.74–95.75%
of those totals. This is a source-and-shape accounting comparison; it is not a
new measurement of allocation events, an expected latency reduction or proof
that every byte can be eliminated. Array headers, temporary storage, frontend
work and application operations lie outside this payload count.

In the preserved qualified source, `Node.cs` sends Conv and ConvRelu to the
provider without a pool. `CPUExecutionProvider.ConvPool.cs` invokes tensor
convolution; `TensorOps.ConvPool.cs` creates the float output with the allocating
`DenseTensor` dimensions constructor. Fused ConvRelu delegates to that path
and applies Relu in place. `ComputationalGraph.TryReleaseValue` returns only
pool-owned arrays. Keeping a context alive cannot reuse these fresh output
arrays under the current implementation. The relevant
[ORT allocator review](../request-contexts/ort-memory-review-20260921.md)
describes Microsoft's different temporary-storage lifetime without claiming
which native paths the installed wheel used.

A pooled-output prototype must retain the existing arithmetic, zero-initialized
destination semantics, geometry validation, output ownership and graph alias
lifetimes. It should preserve existing public tensor overloads and default
cache bounds. Measure allocation and every output bit before complete public
qualification; lower static payload alone is not a performance result.

The [complete census](observations-20260921.json) retains every node, shape,
attribute and independent geometry check. `census.py` reads pinned model,
fixture, trace, allocation and source files from three closed qualifications.
It runs metadata work on CPU 0 and does not mutate any source model. Invoke it
with `C:/Python313/python.exe -X utf8 -B` from the repository root; it refuses
the existing `artifacts/pyannote-convolution-allocation-20260921` directory.
