# Spatial convolution panels: qualified local pyannote candidate

The isolated candidate reduces mean complete 30-second dialogue latency from
38.643 to 30.914 seconds, **20.0%**, in this local comparison. All four fixtures
improve in their aggregate means. All 64 application requests and every saved
graph output pass. AMD timing and production promotion remain pending.

This uses Windows i7-14700KF, logical CPU2, .NET10.0.12, one CLR processor and
normal runtime settings. Four fresh processes run baseline, candidate, candidate,
baseline; each makes one complete warmup pass and three measured passes over
the same four fixtures. Loading is excluded; the public call includes features,
inference, pooling, clustering and owned output construction. No sample is
removed. These are descriptive observations on an active workstation, without
a calibrated confidence or parity claim. There is no new native timing here;
the matched AMD Microsoft ORT baseline remains 46.561/9.270 seconds in

## Imported mechanism

The candidate adapts voice commits `8af223e` and `e35653a` onto source `bb5b092`.
Only `MathOps.cs` and `TensorOps.ConvPool.cs` differ in product sources. It
expands a bounded set of spatial output positions, multiplies the complete
reduction dimension, then copies the result and applies the existing bias.
The current pointwise and explicit experimental segmented routes retain their
precedence. Activation handling, weight caches, matrix kernels and JIT settings
are unchanged. The branch's fused-ReLU argument was omitted to fit master's
existing separate activation contract.

For the dominant `[32,32,3,3]` embedding convolutions, the 256 KiB planning budget
selects 192 output positions. Their convolution patch-plus-output request is
245,760 bytes instead of the original 91,975,680-byte patch. Matrix multiplication
can additionally rent packing storage; scratch-accountant totals accumulate
requests and must not be called peak live memory. Narrow fits retain one
32-column panel, so this is a planning budget rather than a universal hard cap.

The full reduction order is retained, but matrix dispatch depends on tile shape,
so the method does not promise bit equality universally. On all captured
pyannote tensors here, candidate and baseline **do match bits exactly**.

## Correctness and qualification

Each worker also makes 18 graph calls: three dialogue crops, segmentation and
embedding, each with warmup, unprofiled repeat and wall profiling. Across the
four workers, all 72 saved outputs / 11,668,428 values match their corresponding
baseline outputs exactly. Every value passes the unchanged native scaled
`1e-4` bound; maximum error is `3.859400749206543e-5`. Inputs, held outputs and
repeat results remain unchanged. All 64 public calls preserve native speaker
identities/timelines and pass the existing centroid bound. Known silence
intermediate failures remain outside this recorded-dialogue qualification.

The rebuilt baseline has identical IL, resolved operands, locals and exception
clauses for all 3,086 core methods relative to the previously qualified product.
Its captured arrays also match the earlier current-product profile exactly.

The candidate passes 125 focused convolution tests, including the selected
branch's independent double reference cases and new asymmetric-padding,
dilation, tails, offset storage, mutable-weight, scalar/SIMD and empty-batch
coverage. The complete isolated backend suite passes **3,115**, with 93 skipped;
the complete tensor suite passes **342**. Builds have zero warnings/errors.

The unchanged shared-model consumer then verifies e5, DINOv3, ResNet50 and GPT-2:
all 166 arrays / 5,000,814 values pass native bounds, maximum
`1.9885599613189697e-5`. Every e5 output keeps its original bits. Graph mutation,
fingerprint-disabled execution, carried decoder state, input and held-output
contracts pass. This is local affected-model qualification; natural-meeting
replay, other affected audio models and matched AMD improvement remain pending.

The first full qualification attempt is retained: backend tests passed, but
the tensor source scan walked out of the isolated archive because its solution
root marker was omitted. It found old optional-parameter helpers in the main
checkout. Adding the exact `bb5b092` solution file corrects discovery; both
complete suites were rerun in the corrected scope. No product, consumer,
numerical criterion or existing test was changed for this recovery. The
original 341-pass/one-failure tensor log remains available.

All 2,731 comparison resource samples and 91 shared-model samples pass. The
four timing workers, their supervisor, both qualification supervisors and
both shared-model workers are terminal. Comparison limits are 1,800 seconds,
8 GiB RSS, 1 GiB available RAM, 10 GiB preflight RAM and 20 GiB disk. No VM
inference overlapped the live e5 campaign.
