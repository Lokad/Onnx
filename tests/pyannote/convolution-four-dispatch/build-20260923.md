# M29 four-block convolution build

The ordinary AMD Release build passes. Compiled differences are confined to
`ConvBlockedSpatial.Execute` and one added private `Kernel512Four` method.
All 3,162 other existing Core methods, all 697 Data methods and public
declarations remain exact to the selected product. Both original convolution
kernels remain byte-identical in source and compiled inventory. Root source
is unchanged; this build establishes no numerical or performance result.

The new method combines four output blocks with six spatial positions, row
pointers and nine explicitly ordered spatial steps. Selection occurs in
Execute only for sixteen lanes and output channels divisible by 64. This
is a new experiment after the rejected M18 and M28 trials; neither historical
verdict is changed. See the [source review](../integration-review/four-block-dispatch-20260923.md).

SDK 10.0.204, .NET 10.0.8, AMD EPYC 9V74 CPU2, ordinary product dependencies
and no timing/runtime override. Four jobs and 76 resource observations pass;
peak owned RSS is 512,634,880 bytes. Every recorded owner is terminal.
Seven mutation tests against the real compiled inventory pass, rejecting
fallback or Data changes, extra methods, public changes and wrong products.
Non-timing build preflight was fixed at 10 GiB before launch; numerical and
performance work retains the original 12 GiB requirement and live bounds.
