# Winograd numerical feasibility passes on AMD

All87eligible captured stride-one convolutions pass the unchanged Microsoft
ORT scaled error bound of1e-4 in both AVX256 and AVX512. The maximum candidate
error is **1.847744e-6**; the selected direct control reaches3.814697e-6.
Each mode checks98,734,080captured values. Every candidate output hash is
identical across the two instruction widths. This is numerical feasibility,
not a performance result or product integration.

Each mode also passes1,152synthetic cases /3,806,208values against an independent
double-precision direct convolution. The dyadic random, impulse and cancellation
cases happen to be exact; realistic captured inputs provide the rounding-error
exercise. Eight channel pairs, six spatial shapes and all eight bias/residual/
ReLU combinations are retained. Twenty-one nonfinite/overflow/budget refusals,
24alias/extent contracts, repeated calls, held results, read-only operands and
scratch/output sentinels pass in each mode.

The standalone executable contains byte-exact copies of the four selected
direct-kernel source files plus the new transform. Its SHA256 is
`937ab50e8d9cc140d7c27ba9d010bd8fe32638bc115173e436ef44a9646edd84`.
SDK10.0.204/runtime10.0.8, AMD EPYC9V74CPU2; the256worker explicitly disables
AVX512. All seven jobs and135resource observations pass; peak owned RSS is
556,748,800bytes. Every recorded owner is terminal.

The arithmetic intentionally changes finite rounding. That rule was written
before implementation and retains the original native bounds; historical
bit-exact loop trials are not rescored. No current source, graph dispatch,
public API or application/ORT timing changes. Generated-code review and a
separate fixed performance screen must precede any product-design decision.
