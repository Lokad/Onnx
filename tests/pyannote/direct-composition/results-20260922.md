# Isolated direct-output convolution composition

The original two-column component is now composed into a normal isolated
product build. Actual caller validation, full Windows suites and an independent
NuGet consumer pass. Complete-model qualification and fresh AMD application
timing are still required; this result makes no new performance claim.

The accepted application comparison remains **15.465755 s Lokad.Onnx versus
8.952416 s Microsoft ORT**, a ratio of **1.727551**. Pyannote remains the first
optimization priority, followed by Parakeet. Whisper is deferred.

The source archive is root `8b467dc9`. Only `RunTiledBatchFloat` changes among
existing methods; one checked span wrapper and four kernel methods are added.
All 3,107 other Core methods, 697 Data methods and public declarations match
the accepted runtime. The four generated kernel bodies match the successful
[two-column component](../two-column/results-20260922.md) after resolving their
new declaring type. Existing scratch allocation, tensor views, fallback routes
and shared MatMul remain.

The real caller executes all 400 cases in both normal and hardware-disabled
processes. Each mode checks 3,876,816 final buffer positions, including 767,488
NaNs, with grouped batches, multiple tiles, mutable inputs, zero/special values,
Scalar/Simd/Auto policies, declines and guard regions. All non-NaN output bits,
input bits and guard bits match. The normal run records 1,066 differing NaN
payload observations across intermediate batch comparisons; hardware-disabled
records none. Both sides are NaN at every such position.

The independent package consumer imports MNIST, exercises public MatMul and
convolution, verifies input and held-output ownership, and checks all 33,216
values of a tiled convolution. The package contains the exact candidate Core
and retains its sole Google.Protobuf 3.33.5 dependency. All 313 resource samples
pass; peak aggregate owned RSS is 3,207,593,984 bytes. All 58 recorded process
identities are terminal.

## Preserved failures and checker corrections

Two earlier strict-payload checks failed. A separate accepted-baseline self
control then demonstrated six NaN payload changes between cold and warmed
identical calls, with every non-NaN output bit and input bit unchanged. It
reproduced the disputed position: `ffc00000` became `7fc12345`. The baseline
itself therefore disproves a cross-execution payload-stability requirement.
No per-call JIT trace was collected; this observation does not establish which
runtime optimization caused the change.

The checker now follows the repository's existing exceptional-float convention:
exact non-NaN bits and NaN classification, with all payload differences retained
as diagnostics. No model/native tolerance changes. The attempted bias-precedence
product successor is discarded; the original candidate bytes are reused.

The first corrected-contract run completed every numerical and buffer check,
then exposed a harness count error. The schedule has 22 actual shapes, 336
mutable records, 36 policy records and six declines: 400 cases. The asserted
736 double-counted the mutable records. The successor changes only this count
and preserves the failed run. No case was removed.
