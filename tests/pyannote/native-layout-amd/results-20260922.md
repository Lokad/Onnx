# Pyannote native layout confirmed on the AMD target

**ORT executes all 36 embedding convolutions in blocked channel layout.**
The optimized graph contains 16 fused residual additions, 33 ReLU attributes,
one `ReorderOutput` and no `ReorderInput`. The first single-channel convolution
accepts the ordinary input layout. This confirms the earlier Windows graph
finding on the actual AMD installation and identifies a concrete source-review
lead for the remaining Lokad.Onnx gap.

| Model | Original top-level nodes | Optimized nodes | Blocked convolutions | Executed kernel events | Requests |
|---|---:|---:|---:|---:|---:|
| Embedding | 111 | 50 | 36 | 300 | 6 |
| Segmentation | 144 | 50 | 0 | 306 | 6 |

Segmentation retains two ordinary top-level convolutions and four LSTMs. Its
six additional events come from the taken nested branch. Every executed node
resolves to the serialized graph; every top-level node executes six times.
No assembly microkernel dispatch is inferred from these operator names.

Separate fresh processes construct metadata and profile execution. Their two
serialized graphs match byte for byte. Three saved inputs per model run twice:
all **12 arrays / 1,944,738 values** pass the unchanged `1e-4` scaled native
bound; maximum error is **3.693998e-5**. Repeated outputs match exactly, and
inputs and held outputs remain unchanged. These are graph fixture checks,
not another complete diarization accuracy claim.

The target is AMD EPYC 9V74, CPU2 before native imports, ORT 1.29.0, one
intra/inter-op thread, sequential execution, full optimization and no spinning.
Model bytes, interpreter, native packages, inputs and references are pinned.
The workstation's separately pinned ONNX parser reads the collected graphs;
no parser or other dependency was installed on the VM.

All **30 resource observations** pass; peak owned RSS is **209,788,928 bytes**.
Both workers and supervisor PID698830/birth1790069789.55 are terminal. The
12 GiB available / 3 GiB tmpfs preflight, 8 GiB RSS ceiling, 1 GiB available
and tmpfs floors, output limits and 900-second worker limit remain unchanged.

The first stage failed after archive extraction because Python cached the
then-absent tools directory. The explicit `recover_stage.py` preserves that
failure, invalidates the import cache and verifies the same payload before
the sole launch. No payload or diagnostic assertion changed.

Profile events are retained as diagnostic evidence. They do not supply a
matched application speed comparison or select a managed optimization. The next
step is current managed attribution, then one bounded mechanism that includes
layout conversions, preparation, residuals, activations and observable outputs.
