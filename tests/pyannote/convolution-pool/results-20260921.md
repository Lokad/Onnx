# Pyannote convolution output reuse: graph qualification

The isolated candidate reduces repeated embedding allocations from about
166.9 MB to 6.67 MB in both process orders, a 96.0% reduction. All 108 graph
calls preserve every checked output bit, input and held result: 17,502,642
values in total. This is an allocation result. Complete application
qualification and a separate matched latency comparison are still required.

## Implementation and scope

[The candidate patch](candidate-v5.patch) passes the existing execution pool
through float rank-four Conv and fused ConvRelu dispatch. It rents cleared
output storage using the existing lifetime and alias handling. All arithmetic,
geometry planners, public overloads, one-dimensional lowering and double
behavior remain unchanged. The default cache stays at 128 MiB and 256 arrays.
Data retains the qualified request-context implementation.

The candidate Core SHA256 is
`0d098ba5fd3fd8799bb1dd018148123f296802c769db5f6148a1a5fa9d80118e`;
Data is `1d34666456a5da749dc3b40ee25621af0bed806c9167f3ad12e96d0736dca662`.
Instruction inspection verifies 3,095 unrelated Core methods and all 696 Data
methods. Five existing methods and five additions implement the change;
the old private Conv2DFloatCore signature is replaced. One generated initializer
lambda changes ordinal 528 to 530. Its body is identical and the static
constructor differs only at the corresponding function pointer operand.

The initial strict instruction checks rejected two preparations before tests.
Two later preparations each passed 160 focused cases and failed four synthetic
graph cases. The first fixture omitted fused-node and output declarations;
the second incorrectly required a cache hit immediately after an injected
graph failure. Retained diagnostics show that the failed run consumes the
cached buffer, so the first recovery allocates and the following call reuses
storage. Corrected tests require this sequence and retain all output, ownership
and recovery checks. Product bytes are unchanged from the second preparation.
All four failed attempts remain closed and available.

## Validation

On Windows i7-14700KF CPU2, normal .NET 10.0.12, 164 focused tests pass and
31 tests pass with hardware intrinsics disabled. The new tests poison reusable
arrays with NaNs and cover convolution geometry, fused activation, live aliases,
held outputs, injected failure and recovery. The original captured-input
consumer then executes six segmentation/embedding fixtures three times in
fresh, reused and zero-cache contexts, reversing mode order in a second process.

| Forward order | 166,860,713.33 | 6,672,872 | 96.001% |

New pool payload remains 1,280,000 bytes per repeated embedding call, exactly
the final caller-owned output. Reused payload rises from 69,336,960 to
229,101,440 bytes. These are cumulative allocation/reuse counters, not RSS.
All 186 graph resource samples pass, with peak RSS 947,507,200 bytes. Preparation
adds 105 checked resource samples. All recorded processes are terminal.

The original shared-model consumer passes 166 complete native arrays containing
5,000,814 values, with zero arrays changed from its retained predecessor.
This includes the five e5 fixtures under both policies and execution APIs.
Both workers pass all 77 resource samples.

The original complete Parakeet trajectory preserves all 784 arrays and
3,090,494 values bit-for-bit, including transcripts, token/frame limits,
rejection controls and repeat behavior. All 119 resource samples pass.
The three existing native differences remain exactly
`english-16k/step-26/outputs`, `english-frame-limit/step-26/outputs` and
`english-repeat/step-26/outputs`, each with maximum scaled error
0.0002321004867553711. This candidate does not claim to fix them.
