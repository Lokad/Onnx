# Parakeet and pyannote versus Microsoft ORT — 2026-09-19

This supplies the native audio baseline missing from the earlier BENCHMARK.md
update. It measures fresh complete PCM application calls through both engines;
the old reference-generator durations are not used as performance measurements.

Windows 11, Intel Core i7-14700KF (20 physical / 28 logical CPUs), worker affinity
to logical CPU 2 inherited before runtime startup. The supervisor is on CPU 0.
Managed .NET 10.0.12, SDK 10.0.204; ORT 1.29.0 CPU, intra/inter-op 1, sequential,
all optimizations, spinning disabled. Torch and BLAS budgets are one thread.
Managed calls use normal public options, including their internal Memory
execution policy, with no experimental or runtime override flags.

Seconds are the mean of six complete corpus passes per engine. For Parakeet,
one corpus contains twenty clean-English clips from ten speakers, 213.265 audio
seconds, each 4.07–17.96 seconds. For each pyannote row, one corpus is the named
recording. The thirty-second dialogue uses 21 overlapping ten-second windows;
each crop uses one. Crops and full dialogue are correlated. No requests were
discarded. A ratio above one means managed execution took longer.

The [runner documentation](README.md) gives the exact boundaries and commands.
Parakeet includes frontend/encoder/decoder ONNX graphs plus greedy TDT decoding.
Pyannote includes segmentation, embedding encoder and projection ONNX graphs,
Torch features/pooling, native PLDA/VBx clustering and timeline reconstruction.
The same graph sharing policy computes the embedding encoder once per window
for all three masks. Native helper bookkeeping is included. This is an
ORT-backed application comparison, not a claim that every pipeline operation
executes within ORT or that this is the unmodified upstream Python pipeline.

approximately 0.5 seconds. It is neither a memory ceiling nor a per-request
allocation measurement. Constructor observations have different import/setup
boundaries and do not constitute a cold-start comparison.

Foreign activity ranged from 10.96% to 14.62% of
the machine's 28-logical-CPU capacity during the timing processes. These process
snapshot deltas miss some exited/short-lived work and do not locate interference
on a specific CPU. Affinity is verified; exclusive use of the Windows machine
is not asserted. Two visits describe variation, without confidence intervals,
fine timing calibration or a parity claim. These are Intel measurements and
must not be compared directly with the AMD e5 table.
